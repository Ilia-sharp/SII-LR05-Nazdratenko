**Обязательные шаги задания:**
1. Открытый временной ряд + указать источник и лицензию.
2. Загрузка данных и ЯВНАЯ обработка пропусков; никаких «молчаливых» интерполяций длинных дыр.
3. Метод варианта — z-score с окном 24.
4. Результат построчно: `timestamp, value, score, is_anomaly`.
5. Файлы `anomalies.csv` или `anomalies.json` + график `outputs/anomalies.png`.
6. Порог вынесен в YAML или переменную окружения. **Хардкод порога запрещён.**
7. Разбор 5–10 срабатываний: какие реальные, какие ложные.
8. Сравнение с наивным baseline: «вчера» / rolling mean / простой z-score.
9. Описание поведения сервиса, если ряд перестал поступать или стал постоянным.

**Технические требования задания:** Python 3.10+; pandas, numpy, scikit-learn, matplotlib/plotly;
FastAPI — по желанию (обязателен CLI или отчёт); поле `model_version` в JSON/API.

**Минимальный формат результата:**
```json
{"model_version":"anomaly-v1","threshold":0.7,
 "items":[{"timestamp":"2023-01-05T12:00:00","value":912.3,"score":0.95,"severity":"high"}]}
```

**Не требуется:** ARIMA, полноценный мониторинг, обучение на больших данных, второй метод.

**Критерии оценки (100):** рабочий конвейер 30 · отчёт и визуализация 20 · порог/тревоги/пропуски 15 · сравнение с baseline 15 · README и GitVerse 20.

## 4. ДАННЫЕ (реальные, с лицензией)

- Источник: **UCI ML Repository — Individual Household Electric Power Consumption**
  (Hebrail & Gerard, EDF R&D, 2012), лицензия **CC BY 4.0**.
- Скрипт `scripts/prepare_sample.py`: качает архив UCI (~20 МБ), читает колонки
  Date/Time/Global_active_power порциями, агрегирует в среднечасовые значения (кВт),
  сохраняет полный ряд и демо-сэмпл **ноябрь–декабрь 2008 (1464 точки)**; кэш удаляет.
- `data/SOURCE.md`: источник, авторы, лицензия, способ получения, цитирование.
- Формат CSV: `timestamp,value`. Загрузчик принимает также `дата/время/значение/потребление`.

**Критичный подводный камень парсинга дат:** `pd.to_datetime(..., dayfirst=True)`
тихо ПОРТИТ ISO-даты «2008-11-01» → «11 января» (день ≤ 12 меняются местами; дни > 12 дают NaT).
Правильно: определять формат по шаблону — ISO (`^\d{4}-\d{1,2}-\d{1,2}`) парсить БЕЗ dayfirst,
русские `дд.мм.гггг` — С dayfirst; иначе выбирать разбор с меньшим числом NaT.

## 5. МЕТОД И ПОЛИТИКИ (математика)

- `score(t) = |v(t) − mean(окно W)| / std(окно W)`; `is_anomaly = score > threshold`;
  первые W−1 точек не скорятся (прогрев).
- Severity (из конфига): medium ≥ threshold×1.1, high ≥ threshold×1.3 (дефолт порога 3.0σ).
- Пропуски: `max_interp_gap = 3`; короткие дыры — линейная интерполяция по соседним
  точкам (np.interp по позициям s−1 и e+1), длинные и краевые — NaN + `left_blank` в отчёте.
- Flatline: std всего ряда = 0 → все score NaN, тревог нет, баннер «ряд стал константным».
- Stale: при `monitor_freshness: true` возраст последней точки > `stale_after_hours`
  → флаг и баннер «данные не обновляются N часов»; сервис продолжает работать на срезе.
- Baseline-таблица: число тревог, доля %, MAE против опорного прогноза, Жаккар с вариантом.

## 8. ТЕСТЫ (pytest, цель 13)

1) короткая дыра интерполируется с точными значениями; 2) длинная дыра остаётся NaN (left_blank);
3) краевая дыра — left_blank; 4) дубли времени усредняются; 5) z-score ловит инжектированный
выброс (seed фиксировать); 6) константный ряд → flatline, тревог нет; 7–8) границы severity;
9) baseline «вчера» на игрушечном ряде; 10) порог читается из env `ANOMALY_THRESHOLD`;
11) окно из env `ANOMALY_WINDOW`; 12) валидатор диапазонов порога/окна; 13) полный прогон:
структура результата + 4 артефакта + JSON-схема (model_version, threshold, items[timestamp,
value, score, is_anomaly, severity]).
